# TDCP Universal Attendance Management System

Centralized attendance platform for the Tourism Development Corporation of Punjab (TDCP) — Head Office Lahore, regional offices, and resorts.

## Architecture highlights

- **Monorepo:** React (Vite) web dashboard, Node/Express API, Flutter Android app, local integration agent
- **MySQL:** One database (`tdcp_attendance_db`) with **separate physical attendance tables per resort**
- **Automatic provisioning:** Creating a location generates validated table prefixes and all resort attendance tables inside a transaction
- **RBAC + location scope:** JWT access/refresh tokens; resort users only see authorized locations (enforced on the API)
- **Biometric adapters:** Plugin-style device adapters (CSV import verified; ZKTeco TCP probe ready — live protocol pending on-site testing)
- **Timezone:** `Asia/Karachi` for business-date calculations

## Prerequisites

- Node.js 20+
- MySQL 8.0+
- Docker (optional, recommended for MySQL)
- Flutter 3.22+ (for the Android app)

## Quick start

### 1. Configure environment

```bash
cp .env.example .env
# Edit DB_* and JWT_* secrets
```

### 2. Start MySQL

```bash
docker compose up -d mysql
```

Or point `.env` at an existing MySQL 8 instance and create a user with rights on `tdcp_attendance_db`.

### 3. Install, migrate, seed

```bash
cd backend && npm install && npm run migrate && npm run seed
cd ../frontend && npm install
```

Default super admin (change immediately):

- Username: `superadmin`
- Password: `ChangeMe@TDCP2026`

Seeded locations include Head Office Lahore, Patriata, Changa Manga, Hiran Minar, Derawar, Kot Mithan, Taunsa, Daud Khel, Dhanoi, and Lakhwal Dam — each with its own attendance table set.

### 4. Run locally

From the repo root, start the API and web app together:

```bash
npm run dev
```

- API: http://localhost:4000/api/v1/health  
- Web: http://localhost:5173

## API overview

Versioned under `/api/v1/`:

| Area | Endpoints |
|------|-----------|
| Auth | `POST /auth/login`, `POST /auth/refresh`, `GET /auth/me`, `POST /auth/logout` |
| Locations | `GET/POST /resorts`, `PATCH /resorts/:id`, `GET /resorts/regions/list` |
| Employees | `GET/POST /employees`, `POST /employees/:id/transfer` |
| Dashboard | `GET /dashboard/stats` |
| Reports | `GET /reports/attendance` |
| Devices | `GET /devices`, `POST /devices`, `POST /devices/:id/test-connection`, `POST /devices/:id/import-csv` |

## Resort table naming

Prefixes are generated by a controlled registry (never raw user SQL identifiers), for example:

- `tdcp_patriata_attendance_logs`
- `tdcp_patriata_daily_attendance`
- `tdcp_patriata_shift_assignments`
- `tdcp_patriata_attendance_corrections`
- `tdcp_patriata_leave_requests`
- `tdcp_patriata_overtime_records`

## Biometric integration status

| Adapter | Status |
|---------|--------|
| `generic_csv` | Implemented & usable for offline import |
| `zkteco_pull` | TCP reachability implemented; **full log protocol not claimed verified** until tested on TDCP devices |
| Hikvision / Suprema / Anviz | Scaffold only — not implemented |

Do not expose biometric devices on the public internet. Prefer VPN or the local `integration-agent`.

## Production notes

- Set strong `JWT_*` and DB passwords; never commit `.env`
- Terminate TLS at the reverse proxy / load balancer
- Restrict the MySQL app user to required privileges only
- Schedule backups of `tdcp_attendance_db`
- Rotate the default `superadmin` password on first login
